# 15. 三数之和 · 思考总结

## 题目描述

给你一个整数数组 `nums`，判断是否存在三元组 `[nums[i], nums[j], nums[k]]` 满足：
- `i != j`、`i != k`、`j != k`
- `nums[i] + nums[j] + nums[k] == 0`

返回所有和为 0 且不重复的三元组。

**示例：**
```
输入：nums = [-1,0,1,2,-1,-4]
输出：[[-1,-1,2],[-1,0,1]]
```

---

## 最终代码

```python
class Solution:
    def threeSum(self, nums: list[int]) -> list[list[int]]:
        tuple_ans_list = []
        nums.sort()
        for index, num in enumerate(nums):
            target = 0 - num
            left_index, right_index = index + 1, len(nums) - 1
            if index != 0 and nums[index] == nums[index - 1]:
                continue
            while left_index < right_index:
                if nums[left_index] + nums[right_index] == target:
                    tuple_ans_list.append([num, nums[left_index], nums[right_index]])
                    # 前置去重：先跳过重复值，再确定性移动
                    while left_index < right_index and nums[left_index] == nums[left_index + 1]:
                        left_index += 1
                    while left_index < right_index and nums[right_index] == nums[right_index - 1]:
                        right_index -= 1
                    left_index += 1
                    right_index -= 1
                elif nums[left_index] + nums[right_index] < target:
                    left_index += 1
                else:
                    right_index -= 1
        return tuple_ans_list
```

**复杂度：**
- 时间：O(n²)，排序 O(n log n) + 双指针 O(n²)
- 空间：O(1)（不计输出）

## 核心思维模型

1. **排序是前提**：有序才能给双指针提供方向性，sum 大了往左缩，sum 小了往右扩。

2. **子问题转化**：三数之和 → 固定一个数 → 有序数组两数之和，降一个维度。

3. **移动是确定性动作，前置去重保证确定性**：在执行关键移动之前，先清理会干扰结果的重复状态，确保每次落点唯一。这是一种通用思维，适用于所有需要跳过重复的双指针场景。

## 独立思考与踩坑记录

### 坑1：enumerate 解包顺序

```python
# 错误写法
for num, index in enumerate(nums):  # num 拿到的是下标，index 拿到的是值

# 正确写法
for index, num in enumerate(nums):
```

`enumerate` 返回 `(index, value)`，顺序不能反。

### 坑2：sort() 返回 None

```python
nums = nums.sort()  # nums 变成 None 了！
nums.sort()         # 正确：原地排序，不要赋值
```

### 坑3：内层用 enumerate 还是双指针

最初内层用 `enumerate(nums[index+1:])` 遍历，这是暴力 O(n²) 内层，加上外层是 O(n³)。

正确做法是双指针：`left = index+1`，`right = len(nums)-1`，用 `while left < right` 驱动。

### 坑4：去重用 `not in list` 导致超时

```python
if [num, nums[left], nums[right]] not in tuple_ans_list:  # O(n) 查找，整体 O(n³)
```

应该从源头用跳过重复元素的方式避免重复，而不是事后检查。

### 坑5：去重误杀合法答案

对 `[-2,0,1,1,2]`，找到 `[-2,0,2]` 后 left 移到第一个 `1`，此时：

```python
# 错误：先移动再去重
left_index += 1
right_index -= 1
while nums[left_index] == nums[left_index + 1]:  # 两个1相等，跳过了！
    left_index += 1
# 结果：[-2,1,1] 被漏掉
```

### 独立推导出的正确去重思路

> **移动是确定性动作，前置去重保证确定性。**

找到答案后，先跳过当前值后面的重复值，再执行移动：

```python
# 正确：先去重再移动
while left < right and nums[left] == nums[left + 1]:
    left += 1
while left < right and nums[right] == nums[right - 1]:
    right -= 1
left += 1   # 最后确定性地移动一步
right -= 1
```

这样移动落点是唯一确定的，不会误杀合法答案。

## 思路推导过程

### 第一反应：暴力法

固定一个数，内层再用两层循环枚举剩余两个数 → O(n³)，必然超时。

### 关键问题：内层两个指针怎么走？

最初的困惑：
- 两个指针是从左到右？还是一左一右往中间？
- 组合不用考虑顺序，那内层是不是要固定左边再循环右边？

**突破口：先排序，把问题转化。**

排序之后，三数之和变成了一个子问题：

> 有序数组中，找两个数之和 = target

### 为什么一左一右可以不遗漏？

有序数组，`left` 指向最左，`right` 指向最右：

- `sum < target` → 需要变大 → **left 右移**（左边是最小值，右移让 sum 增大）
- `sum > target` → 需要变小 → **right 左移**（右边是最大值，左移让 sum 减小）
- `sum == target` → 找到答案

每次移动都是**确定性的**，不会遗漏任何组合。排序保证了方向性，这是双指针能工作的前提。

### 关于组合 vs 排列

排序天然解决了排列问题：`[-1,0,1]` 和 `[1,0,-1]` 排序后是同一个。只要保证 `left < right`，就不会出现重复排列。
